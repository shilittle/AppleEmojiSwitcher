## 本机调查结果

系统为 Windows 11 23H2 x64，Build 22631.6199。输入宿主来自系统包 `MicrosoftWindows.Client.CBS_1000.22700.1108.0_x64__cw5n1h2txyewy`。

| 组件 | SHA-256 |
| --- | --- |
| `TextInput.dll` | `5121e295fd7a267849a5d636ed63a718318ec8f01c0575fa14d9e8b906395d77` |
| `WindowsInternal.ComposableShell.Experiences.SuggestionUIUndocked.dll` | `d9d5cd9605d38a45ab8fcd256a65068b530215eb4924fac11cd709377e108c42` |
| `AdvancedEmojiDS.dll` | `84430e79468cd93cbd36062a75b1352b8ecc07ceb24f2f9f4518794cca0948cb` |

微软公开调试符号与上述本机文件匹配。分析表明，原生面板的分类、搜索和点击输入需要同时覆盖以下链路：

- `NativeBridge::GetExpressiveTextCategoriesInfo`：分类信息；
- `NativeBridge::GetExpressiveTextItems` / `LayoutDataAdapter::GetItemsOfType`：分类条目；
- `ExpressiveTextSearchDataSource`：异步搜索与结果更新；
- `NativeBridge::HandleExpressiveTextSelection`：选中后的输入提交。

这些符号位于 `SuggestionUIUndocked.dll`。只改 `AdvancedEmojiDS` 的搜索结果，不能证明分类目录或点击输入已经支持新序列。`AdvancedEmojiDS` 通过内部 WinRT 接口工作，不能按同名字符串猜测存在公开 C 函数导出。

独立只读探针在普通测试进程中创建了本机 `AdvancedEmojiDS` 对象并以 `en-US` 初始化。8 个新增基础表情的描述查询均返回空字符串句柄，旧表情 `😀` 返回 `grinning face`。这证明该版本的英文描述查询缺少这些新条目，与用户观察相符；它不等同于分类、中文搜索或点击输入的验收。探针没有加载到输入宿主。

组件哈希和符号位置只是调查记录，**不是已通过测试的兼容列表**。还需要在原生面板中核对实际调用约定、JSON 数据结构、异步回调和字符串所有权，才能确定最终注入实现。
